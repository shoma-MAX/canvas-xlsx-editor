# 実装と検証記録

2026-11-05 / 0.1.1。仕様書の確定事項と検証仮説を区別し、未知のブック機能は読み取り専用にする初期版。

## ソースと構成

- フォーク元: `ibisjp/ibis-office`、基点 `1d5dba02003d430d30f147f8c6a673559e3c147b`。
- `engine/`: 独立Cargoワークスペース。`ibis-doc-model` の `Document` / `SheetCommand` と `ibis-pptx::Source` を使用。
- 履歴: 上流の逆コマンド方式。通常セル・書式変更は差分。構造変更は上流がブック内の関連構造を保持するため、すべての操作が厳密な差分とは限らない。
- `webview/`: 仮想Canvas、編集用textarea、ファイルごとのclassic Worker。WASMは拡張ホストからbase64で一度渡し、Workerで初期化。VS CodeのWebviewリソース配信におけるバイナリ変換やWorkerからの取得タイムアウトを避ける。
- `src/`: CustomDocumentの編集通知・Undo/Redo・保存・別名保存・revert・バックアップ。対象はローカルファイル。
- 上流のGPUI本体・フォークのパッチは拡張機能のビルド対象外。AGPL/NOTICEはVSIXに同梱し、UIにも帰属リンクを表示。

## 実施した検証

- Rust `wasm32-unknown-unknown` のcheckとrelease build、TypeScript型検査、VSIX生成。
- WASMを実行するNodeテスト: 値/数式の編集、依存数式の再計算、Undo/Redo、書式、文字列置換、内部コピーの相対/絶対参照、行列挿入削除、シート追加/改名/移動/削除、サイズ、値フィルター、値だけのソート、未対応関数の明示、独立したブック、範囲上限、ZIP展開量上限。
- 保存したXLSXを再読込して値・数式・書式・フィルター等を確認。未編集の独自XMLパーツを含むfixtureを使用。高度機能を持つブックでは編集拒否と元バイト列の返却を確認。
- ファイル保存テスト: 外部変更を検出して元のファイルを保持、一時ファイルの後始末、通常保存。
- Custom Editor providerのAPIテスト: 通常保存、別名保存、バックアップ作成/復元、外部変更時の保存拒否、revert。
- Playwright / ChromiumのCSP有効ハーネス: Worker起動、F2編集、数式表示、検索置換、200%ズーム、保存RPC、変更通知数。
- **macOS上の一時プロファイルのVS Code 1.145.0**: Custom Editorを選択して起動、`B2:10→42` を編集、Undoで10、Redo後にCmd+Sで保存。実際のZIP内でB2=42、C2の数式=B2*2/計算値84、B4のSUM計算値47を確認。
- 通常利用中のVS Codeプロファイルへのインストールや設定変更はしていない。

## 実測と限界

小さい合成ブックのNode/WASM初回ロード＋編集＋保存再読込のテストは約30ms、同じプロセスで後続の操作テストは数ms。これは小さいfixtureの計測であり、大規模ブックの性能保証ではない。生成WASMは約14.3MiB、VSIXは約4.0MiB。WASMのbase64転送・復号には一時的な追加メモリが必要。

セル取得は表示範囲のみ。位置の計算は疎な行列サイズ情報を使い、100万要素のJS配列を作らない。WASM側の元ブック・上流モデル・履歴・保存検証用の一時出力はメモリを使う。ZIP展開量の上限は実際の総メモリ使用量の上限ではない。

## 未検証・保留

- 日本語OS IMEの実機変換、音声入力、長時間の編集、アクセシビリティの実用性。
- Windows/Linux、VS Code最小対応版1.95、他の拡張機能との競合、通常プロファイルでの運用。
- 実際の大量データ・多数シート・複雑な関数・日付/数値形式・Excelでの表示互換。
- 障害や再起動を伴うVS Code Hot Exit、実際の電源断、同時書き込み。バックアップのAPI経路はテスト済み。
- 行列の非表示とフィルターは描画に反映するが、特殊な大量連続非表示の応答性は未計測。
- 枠固定とウィンドウ分割は未採用。

本版の読み取り専用判定や往復テストは、あらゆるXLSXの完全保持を保証しない。未対応の保存はエラーを返し、元ファイルへ書き込まない。

## 0.1.1の修正

共有文字列を含むXLSXで文字を変更すると、`xl/sharedStrings.xml` の正常な更新を未編集パーツの変更と誤認して保存を拒否する不具合を修正。共有文字列パーツをワークブックのリレーションから特定し、既存の共有文字列エントリー（未使用・装飾付きも含む）の順序とXMLを保持したままの追加・参照数更新を許可する。通常名と別パスの共有文字列fixtureで日本語編集、繰り返し保存、再読込後の編集、Undo後の保存を確認。全17件のテストと型検査が通過。ユーザーの実際の `プロット.xlsx` は取得・変更していない。
